## Alert Manager
*   **Files**: `keep/api/routes/alerts.py`, `keep/common/event_management`.
*   **Responsibility**: The high-level management of alerts.
    *   **API**: Handles CRUD operations, history querying, and dashboard data.
    *   **Logic**: The `AlertDeduplicator` service manages the complexity of identifying duplicate alerts and updating existing ones.

## Event Handler Service
*   **Files**: `keep/event_handler`, `keep/common/event_management/process_event_task.py`.
*   **Responsibility**: The operational core that processes incoming events.
    *   **Consumption**: Polls Redis or subscribes to Kafka.
    *   **Pipeline**: Runs the `process_event` task which orchestrates parsing, enrichment, deduplication, and saving.

## Messaging Layer
*   **Files**: `keep/common/core/messaging.py`.
*   **Abstractions**:
    *   **EventProducer**: Interface for sending messages (implemented by `RedisEventProducer` and `KafkaEventProducer`).
    *   **EventConsumer**: Interface for receiving messages.
*   **Flexibility**: Allows switching the underlying infrastructure (Redis vs Kafka) via configuration variables (`MESSAGING_TYPE`) without changing application code.

## Workflow Engine
*   **Files**: `keep/workflowmanager`.
*   **Concepts**:
    *   **Step**: A single unit of work (e.g., "Send Slack Message").
    *   **Context**: Data passed between steps (available as `{{ steps.step_id.results }}`).
    *   **Providers**: The bridge to external tools.

## Providers System
*   **Factory Pattern**: `ProvidersFactory` dynamically loads providers based on configuration.
*   **BaseProvider**: All providers inherit from `BaseProvider`, ensuring a consistent interface (`notify`, `query`).
*   **Adding a Provider**: Create a new class in `keep/providers`, implement the standard methods, and register it.
